# FinanceTracker

## Решения по модели транзакции

- Сумма хранится в `BigDecimal` для точных десятичных расчётов.
- Категория обязательна: она нужна для отчётов; для нетипичных операций предусмотрена `OTHER`.
- Конструктор `Transaction` проверяет описание, положительную сумму, тип, дату и категорию.
- Эти проверки находятся в сущности, чтобы нельзя было создать заведомо некорректную транзакцию.
- `TransactionService.add()` проверяет, что в сервис не передали `null`.
- `Transaction` сделана классом: поля, конструктор и методы чтения здесь видны явно, что полезно при изучении объектной модели Java.
- `record` тоже подошёл бы для такой модели, но на этом этапе выбран обычный класс.
