# FinanceTracker

Учебный проект на Java для учёта личных доходов и расходов. Операции сохраняются в CSV и восстанавливаются при следующем запуске. На их основе приложение рассчитывает баланс и отчёты по расходам.

Текущая версия в Maven — `1.0-SNAPSHOT`. Точка входа `Main` выбирает файл хранения, загружает данные и запускает интерактивное меню `ConsoleApplication`. Через меню можно добавлять операции, просматривать их с UUID, получать баланс и удалять операции по UUID.

## Возможности

- Консольное меню: добавление, просмотр, баланс, удаление по UUID и выход.
- Добавление операций с описанием, суммой, типом, датой и категорией; UUID создаётся автоматически.
- Просмотр операций в порядке добавления с UUID для последующего удаления.
- Расчёт баланса: доходы минус расходы.
- Повторный ввод команды, полей операции и UUID при ошибке.
- Завершение по команде выхода или EOF без сохранения незавершённой операции.
- Хранение в памяти или CSV через общий интерфейс репозитория.
- Экспорт и чтение CSV с сохранением UUID, запятых, кавычек и переносов строк в описании.
- Проверка входных данных, заголовка CSV и уникальности UUID.
- Выбор файла хранения через аргумент командной строки.
- Диагностика ошибок запуска и сохранения с указанием пути и причины; продолжение меню после неудачной записи.

Через Java API сервиса также доступны поиск по UUID, категории и диапазону дат с включёнными границами, сортировка по дате, расходы по категориям, средний расход, крупнейшие расходы, самая затратная категория и месяц с наибольшими расходами с учётом года. Для этих отчётов, поиска и отдельного экспорта команд в меню пока нет.

## Запуск

### IntelliJ IDEA

Открыть проект как Maven-проект, дождаться загрузки зависимостей и запустить `com.learning.Main` зелёной кнопкой. Рабочей папкой в настройках запуска должна быть корневая папка проекта. Команды меню вводятся в окне **Run** запущенного приложения; окно **Terminal** используется для команд Maven и оболочки.

### Терминал

После сборки скопировать зависимости для запуска:

```shell
mvn dependency:copy-dependencies -DincludeScope=runtime -DoutputDirectory=target/dependency
```

Команда использует [Maven Dependency Plugin](https://maven.apache.org/plugins/maven-dependency-plugin/examples/copying-project-dependencies.html) и копирует также транзитивные зависимости. После `mvn clean` её нужно выполнить снова.

На macOS и Linux:

```shell
java -cp "target/classes:target/dependency/*" com.learning.Main
```

На Windows:

```shell
java -cp "target/classes;target/dependency/*" com.learning.Main
```

### Выбор файла хранения

Без аргументов приложение использует `data/transactions.csv`. Чтобы выбрать другой CSV, передать один аргумент после имени класса.

На macOS и Linux:

```shell
java -cp "target/classes:target/dependency/*" com.learning.Main data/path-practice.csv
```

На Windows:

```shell
java -cp "target/classes;target/dependency/*" com.learning.Main data/path-practice.csv
```

Допускаются относительные и абсолютные пути. Относительный путь отсчитывается от рабочей папки процесса. Если путь содержит пробелы, передать его в двойных кавычках, например `"data/my transactions.csv"`.

В IntelliJ IDEA открыть **Run → Edit Configurations**, выбрать конфигурацию **Application** для `com.learning.Main` и указать путь в поле **Program arguments**, например `data/path-practice.csv`. Если конфигурации нет, создать её через **＋ → Application**. Поле **Working directory** определяет рабочую папку для относительного пути.

Пустой аргумент или аргумент только из пробельных символов выбирает стандартный путь `data/transactions.csv`. Больше одного аргумента или недопустимый путь приводят к сообщению в stderr и завершению с кодом `1`; меню не запускается.

### Первый запуск

По умолчанию `Main` использует относительный путь `data/transactions.csv`. При запуске из другой рабочей папки приложение будет искать данные в её подкаталоге `data`. Другой путь можно передать аргументом, как описано выше.

Если выбранного файла ещё нет, репозиторий начинает работу пустым и продолжает использовать выбранный путь. Чтение само по себе не создаёт папку и файл; они появляются при первом успешном сохранении операции.

После успешной подготовки хранилища появляется меню:

```text
1 — Добавить операцию
2 — Показать операции
3 — Показать баланс
4 — Удалить операцию
0 — Выйти
```

## Работа с меню

Команды вводятся отдельной строкой. После выполнения действия приложение снова показывает меню.

| Команда | Действие |
| --- | --- |
| `1` | Последовательно запросить поля и добавить операцию |
| `2` | Показать операции с UUID; для пустого списка вывести «Операций пока нет» |
| `3` | Показать баланс; для пустого хранилища — `Баланс: 0.00` |
| `4` | Запросить UUID и удалить соответствующую операцию |
| `0` | Завершить приложение |

### Добавление операции

После команды `1` поля запрашиваются в следующем порядке:

| Поле | Что вводить |
| --- | --- |
| Описание | Непустой текст одной строкой; пробелы по краям удаляются |
| Сумма | Положительное число, например `150.50`; десятичный разделитель — точка, не более двух знаков после неё |
| Тип | `1` — доход (`INCOME`), `2` — расход (`EXPENSE`) |
| Дата | Дата ISO, например `2026-10-15` |
| Категория | `1` — `SALARY`, `2` — `RENT`, `3` — `TRANSPORT`, `4` — `FREELANCE`, `5` — `FOOD`, `6` — `UTILITIES`, `7` — `OTHER` |

При ошибке повторяется ввод соответствующего поля, ранее введённые корректные значения сохраняются. Проверки допустимости данных также остаются в модели `Transaction`.

Операция создаётся после полного ввода и передаётся сервису один раз. Сообщение «Транзакция успешно добавлена!» появляется только после успешного сохранения. Конец входного потока (EOF) в меню или при вводе любого поля завершает приложение; незавершённая операция не сохраняется.

### Просмотр и удаление

Команда `2` показывает UUID перед результатом форматтера. Например:

```text
11111111-1111-1111-1111-111111111111 | 01.10.2026 | SALARY | Зарплата | 1000.00
22222222-2222-2222-2222-222222222222 | 07.10.2026 | FOOD | Продукты | 150.50
```

Для удаления введи `4`, затем скопированный UUID операции. Неверный формат UUID допускает повторный ввод. Корректный UUID отсутствующей операции даёт сообщение «Транзакция с указанным UUID не найдена» и возвращает к меню. Успешное удаление сразу сохраняется в CSV.

### Проверка между запусками

Для учебной проверки выбери отдельный файл, например `data/menu-practice.csv`, который ещё не содержит операций:

1. Добавь доход `1000.00` и расход `150.50`.
2. Вызови команды `2` и `3`: должны отображаться обе операции с UUID и баланс `849.50`.
3. Выйди командой `0` и запусти приложение с тем же путём.
4. Проверь восстановление операций и их UUID.
5. Удали расход по UUID, выйди и запусти приложение снова.
6. Проверь, что остался доход с прежним UUID и баланс `1000.00`.

Папка `/data/` исключена из Git через `.gitignore`, чтобы личные операции не попадали в репозиторий.

## Обработка ошибок

| Ситуация | Поведение приложения |
| --- | --- |
| Неверная команда или поле ввода | Сообщение в обычном выводе и повторный запрос |
| Лишние аргументы или недопустимый путь | Сообщение в stderr; меню не запускается, код завершения `1` |
| Ошибка чтения, каталог вместо CSV, неверные данные или повреждённый синтаксис CSV | Сообщение в stderr с путём и деталями; меню не запускается, исходный файл не заменяется пустым хранилищем, код завершения `1` |
| Неудачное сохранение добавления или удаления | Сообщение в stderr с действием, путём и причиной; успех не сообщается, память остаётся прежней, меню продолжает работу |
| Команда `0` или EOF | Нормальное завершение с кодом `0` |

Неуспешная запись автоматически не повторяется. Пока файловая проблема не устранена, последующие попытки записи также могут завершаться ошибкой. Ошибка отдельной команды не меняет статус нормального завершения меню на `1`.

## Пример использования Java API

Этот пример можно выполнить внутри метода с импортами из пакета `com.learning`, а также `BigDecimal`, `Path` и `LocalDate`:

```java
TransactionRepository repository =
        new FileTransactionRepository(Path.of("data", "transactions.csv"));
TransactionService service = new TransactionService(repository);

Transaction expense = new Transaction(
        "Обед",
        new BigDecimal("350.00"),
        TransactionType.EXPENSE,
        LocalDate.of(2026, 10, 8),
        Category.FOOD
);

service.add(expense); // Операция сразу сохраняется в CSV.
System.out.println(service.findById(expense.getId()));
System.out.println(service.expensesByCategory());

boolean removed = service.removeById(expense.getId());
System.out.println(removed); // true; удаление также сохранено в CSV.
```

Для хранения только в памяти передать в сервис `new InMemoryTransactionRepository()`. Конструктор `new TransactionService()` тоже выбирает эту реализацию.

Отдельный экспорт текущего снимка операций:

```java
new CsvTransactionExporter().export(
        service.findAll(),
        Path.of("data", "export.csv")
);
```

Экспорт перезаписывает файл и при необходимости создаёт родительские папки. Метод объявляет `IOException`: вызывающий код должен обработать её или объявить `throws IOException`.

## Архитектура

Исходники находятся в `src/main/java/com/learning`, тесты — в `src/test/java/com/learning`.

| Компонент | Ответственность |
| --- | --- |
| `Main` | Выбирает путь, обрабатывает ошибки подготовки хранилища, создаёт компоненты и запускает консоль; `run()` принимает потоки и возвращает статус, `System.exit()` остаётся в `main()` |
| `ConsoleApplication` | Управляет меню, читает и преобразует ввод, показывает UUID и результаты, обрабатывает EOF и ошибки сохранения команд |
| `Transaction`, `TransactionType`, `Category` | Модель операции и проверка допустимых значений |
| `TransactionService` | Добавление, поиск, удаление, фильтрация и бизнес-расчёты; получает репозиторий через конструктор |
| `TransactionRepository` | Общий контракт сохранения, поиска и удаления |
| `InMemoryTransactionRepository` | Хранение операций в `LinkedHashMap` по UUID |
| `FileTransactionRepository` | Загрузка из CSV и сохранение изменений в файл; держит текущие данные в памяти |
| `TransactionFormatter` и его реализации | Представление операции для консоли или CSV |
| `CsvTransactionExporter` | Запись заголовка и операций в CSV в UTF-8 |
| `CsvTransactionReader` | Разбор CSV, проверка полей и восстановление операций с исходными UUID |

Сервис зависит от интерфейса репозитория. Поэтому способ хранения можно выбрать при создании сервиса, сохранив ту же бизнес-логику. Консоль получает сервис, `TransactionFormatter`, `Scanner`, потоки обычного вывода и ошибок и путь хранения через конструктор. Путь нужен для диагностики; чтением и записью CSV занимается репозиторий.

В проекте используются Repository для доступа к данным и Strategy для заменяемого форматирования. Ответственности разделены между моделью, сервисом, хранением и консолью; зависимости передаются через конструкторы. `Transaction.restore(...)` — статический фабричный метод. Factory Method, Builder и Singleton разобраны на отдельных учебных примерах и в основной сценарий приложения не внедрены.

### Контракт репозитория

- `save` добавляет новую операцию. Повторный UUID вызывает `IllegalArgumentException`, существующая операция не заменяется.
- `findById` возвращает `Optional.empty()`, если UUID неизвестен.
- `findAll` возвращает неизменяемый снимок списка в порядке добавления. Последующие изменения репозитория не меняют ранее полученный снимок.
- `deleteById` удаляет указанную операцию. Неизвестный UUID не меняет состояние.
- `null` в аргументах `save`, `findById` и `deleteById` вызывает `IllegalArgumentException`.

Файловый репозиторий читает данные при создании. При изменении он сначала готовит копию `nextState`, записывает её во временный файл в той же папке и выполняет атомарное перемещение в целевой путь. Данные в памяти обновляются после успешного сохранения. Ошибки файлового ввода-вывода передаются как `UncheckedIOException` с исходной причиной; ошибка очистки временного файла сохраняется как suppressed у исходной причины. Эти гарантии не заменяют резервное копирование или координацию нескольких процессов.

## Формат CSV и модель операции

Заголовок обязателен; названия и порядок колонок должны совпадать:

```text
id,title,amount,type,date,category
```

| Поле | Формат и ограничения |
| --- | --- |
| `id` | UUID; уникален в файле и сохраняется при восстановлении |
| `title` | Непустое описание; допускаются запятые, кавычки и переносы строк |
| `amount` | Положительная десятичная сумма с точкой, не более двух знаков после неё |
| `type` | `INCOME` или `EXPENSE` |
| `date` | Дата ISO: `yyyy-MM-dd` |
| `category` | `SALARY`, `RENT`, `TRANSPORT`, `FREELANCE`, `FOOD`, `UTILITIES` или `OTHER` |

Экспорт заключает все значения в двойные кавычки. Кавычка внутри описания удваивается: описание `Кафе "У дома"` записывается как `"Кафе ""У дома"""`. Перенос строки внутри поля сохраняется, поэтому одна CSV-запись может занимать несколько физических строк.

Файл только с заголовком означает пустое хранилище. Файл без заголовка, неверные значения или повторные UUID приводят к ошибке загрузки.

Решения по модели:

- Сумма хранится в `BigDecimal` для точных десятичных расчётов и приводится к двум знакам после точки. Для среднего расхода используется округление `HALF_UP`.
- Тип операции определяет доход или расход; сумма в обоих случаях положительная.
- Категория обязательна для отчётов. Для нетипичных операций предусмотрена `OTHER`.
- `Transaction` неизменяема: поля `final`, доступны методы чтения, сеттеров нет.
- Новый объект получает случайный UUID. `Transaction.restore(...)` восстанавливает сохранённый UUID и применяет те же проверки, что создание новой операции.
- Проверки находятся в модели, чтобы нельзя было создать некорректную операцию. `TransactionService.add()` дополнительно проверяет `null` и повторный UUID.
- Выбран обычный класс: поля, конструктор и методы чтения видны явно, что полезно при изучении объектной модели Java. Для такой модели также подошёл бы `record`.

## Известные ограничения

- Меню поддерживает добавление, просмотр, баланс и удаление; поиск, дополнительные отчёты и отдельный экспорт доступны через Java API.
- Консоль читает описание одной строкой; многострочные описания поддерживаются моделью и CSV.
- Редактирование существующей операции не реализовано; доступны добавление и удаление.
- Все операции загружаются в память, а каждое изменение перезаписывает весь CSV. Проект рассчитан на небольшие наборы данных.
- Репозитории не поддерживают одновременную работу нескольких потоков или процессов. Изменения файла извне после создания репозитория автоматически не подхватываются.
- Сохранение требует поддержки атомарного перемещения и замены целевого файла файловой системой. Если операция не поддерживается, сохранение завершится ошибкой.
- Ошибка чтения или неверные данные останавливают запуск `Main`; восстановление повреждённого файла и резервное копирование пока не реализованы.
- Валюта отдельно не хранится; расчёты предполагают одну общую валюту.
- JAR собирается без зависимостей и без настройки для `java -jar`; запуск описан выше через classpath.
